# k6 test standard

[k6](https://grafana.com/docs/k6/latest/) smoke, load, and stress tests. Each project
packages them as its own service that runs inside the cluster: locally on demand through
Tilt, and on a schedule in higher environments. Scripts follow `typescript.md`.

## Layout

```
<project>/
├── test/k6/
│   ├── Dockerfile            # FROM grafana/k6:<pinned version>, copies the scripts
│   ├── lib/                  # shared helpers: config, checks, request builders
│   ├── smoke/<flow>.ts
│   ├── load/<flow>.ts
│   └── stress/<flow>.ts
├── deployments/k6/
│   ├── base/                 # one CronJob per test type (higher environments)
│   └── overlays/local/
└── tilt/perf-test-runner.tiltfile   # local k6 resources, loaded by the project Tiltfile
```

## Test types

| Type   | Purpose                                         | Shape                                  |
|--------|-------------------------------------------------|----------------------------------------|
| smoke  | The system works under minimal load             | 1 to 2 virtual users, about 1 minute   |
| load   | Behaviour under expected traffic                | Ramp to expected users, hold, ramp down |
| stress | Behaviour and recovery above expected traffic   | Ramp beyond expected users, then down  |

## Script rules

- Scripts are TypeScript. k6 strips types without checking them, so `tsc --noEmit` with
  `@types/k6` type-checks them.
- Every script exports `options` with `scenarios` and `thresholds`. Thresholds are the
  pass and fail criteria: at minimum `http_req_failed` (error rate) and
  `http_req_duration` percentiles, plus a `checks` rate.
- Every request is verified with `check()`. A request without a check proves nothing.
- Tag requests with `name` (the route template, such as `GET /appointments/{id}`) so
  metrics group by endpoint instead of exploding per URL.
- Configuration comes from `__ENV` through `lib/config.ts` (base URL, credentials),
  never hard-coded hosts or secrets.
- Large input data loads once through `SharedArray`.
- Flows are named in domain language (`book_appointment.ts`), matching `GLOSSARY.md`.

## Results

Results go to otel-lgtm through k6's built-in OpenTelemetry output:

```
k6 run -o opentelemetry <script>.ts
```

The CronJob sets `K6_OTEL_GRPC_EXPORTER_ENDPOINT`, `K6_OTEL_EXPORTER_PROTOCOL`, and
`K6_OTEL_SERVICE_NAME=<project>-k6`.

## Schedules and overlap

The base CronJobs share one schedule cycle (every 4 hours) with staggered start times, so
no two test types run at once:

| Test type | Schedule         | `activeDeadlineSeconds` |
|-----------|------------------|-------------------------|
| smoke     | `0 */4 * * *`    | 600 (10 minutes)        |
| load      | `15 */4 * * *`   | 2700 (45 minutes)       |
| stress    | `15 1-23/4 * * *`| 2700 (45 minutes)       |

- Every CronJob sets `concurrencyPolicy: Forbid`.
- A script's total duration stays under its deadline, which stays under the gap before
  the next test type starts.
- Overlays may override a schedule; any override keeps the types from overlapping.
- Locally, the project's `tilt/perf-test-runner.tiltfile` declares one manual resource
  per test type (`auto_init=False`), named `<project>-k6-<type>`. Run them from the Tilt
  UI or with `make smoke`, `make load`, or `make stress` (`PROJECT=<project>`).
