# Go standard

Go code follows, in order of precedence:

1. [Google Go Style Guide](https://google.github.io/styleguide/go/) (guide, decisions, best practices)
2. [Effective Go](https://go.dev/doc/effective_go)
3. [Go Code Review Comments](https://go.dev/wiki/CodeReviewComments)

Package layout follows `go-package-structure.md`. Logging and tracing follow
`observability.md`. The repository `.golangci.yml` is the source of truth for linters: when
this document and that file disagree, the file wins. Linters catch mechanical issues; the
judgment rules below still need a reviewer's eye.

## Style

- Names are short, idiomatic, and free of stutter: `appointment.Repository`, not
  `appointment.AppointmentRepository`.
- Packages are singular, lowercase, one word, no underscores or hyphens.
- Receivers are one or two letters, the same for every method of a type.
- Return early; keep the happy path at the left margin.
- Small interfaces, defined by the consumer (the package that uses them), named for the
  behaviour (`Notifier`, `Scheduler`). Accept interfaces, return concrete types.
- Name interface method parameters; the interface is the port's documentation.
- Composition over abstraction. Add an interface when a second implementation or a test
  boundary needs it, not before.
- A typed value becomes a string through its `String()` method, never `string(v)`. If a
  hand-written type lacks `String()`, add it first.
- `context.Context` is the first parameter of any function that does I/O, blocks, or
  starts work that can be cancelled. Never store it in a struct.
- Every goroutine has an owner that waits for it to finish (`errgroup.Group`,
  `sync.WaitGroup`) and a way to stop it (context cancellation).
- Configuration comes from environment variables parsed once at startup into a typed
  struct in `internal/config`.

## Errors

- Check every error. Discard one with `_` only with a comment saying why it cannot fail
  or why failure is harmless.
- Wrap with context on the way up: `fmt.Errorf("book appointment %s: %w", id, err)`. The
  message says what was being attempted; lowercase, no trailing punctuation.
- Sentinel errors are `ErrX` variables; error types are `XError`. Compare with
  `errors.Is` and `errors.As`.
- An error is logged once, at the boundary that handles it (ingress handler, consumer,
  `main`). Everywhere else it is returned. See `observability.md`.
- Panics are for programmer errors that make continuing unsafe, never for control flow.

## Comments

The repository comment rules in `AGENTS.md` apply. Go adds:

- Every exported package, type, function, method, constant, and variable has a doc
  comment.
- Doc comments are full sentences that start with the name and end with a period:
  `// Book reserves the slot for the patient.`
- A package comment (`// Package appointment manages ...`) sits in the file named after
  the package.
- Exported API comments say what the element does and how to use it safely (concurrency
  safety, nil handling, ownership of returned values).
- Link related identifiers with doc links: `[Repository]`, `[time.Duration]`.
- Inside function bodies, comment only logic a reader cannot follow from the code.

## Testing

The repository testing rules in `AGENTS.md` apply. Go specifics:

- **Assertions** use `github.com/stretchr/testify`. Use `require` when a failure makes the
  rest of the test meaningless (an unexpected error, a nil result), `assert` otherwise.
- **Black-box packages**: tests live in `package <name>_test` and use the exported API.
- **Table-driven** tests use a slice of anonymous structs and `t.Run(tc.name, ...)`.
  Write a table only when cases share one shape; separate tests read better otherwise.
- **Parallel by default**: call `t.Parallel()` at the top of each test and subtest. Tests
  never share mutable state or package variables.
- **No sleeping**: synchronize with channels, `sync.WaitGroup`, or context cancellation.
  Use `testing/synctest` for code that depends on time.
- Use `t.Context()` for the test's context and `t.TempDir()` for files.
- **HTTP handlers** are tested through `net/http/httptest`.
- **Fakes** are generated by [mockery](https://vektra.github.io/mockery/) v3 from
  `<project>/.mockery.yml`, never with `//go:generate` comments. Each mocked package gets
  a sibling `<pkg>mock` package. Only `_test.go` files import it, so mocks never reach a
  production binary. Regenerate with `make go-mocks`.
- **Integration tests** (`services/<svc>/test/integration/`) use the infrastructure Tilt
  runs. Each test creates its own database from the migrated template
  (`CREATE DATABASE <name> TEMPLATE <service>_template`) and drops it in `t.Cleanup`.
- **Acceptance tests** (`<project>/test/acceptance/`) follow `docs/workflow/atdd.md`.
- **Traces in tests**: assert spans in-process with
  `go.opentelemetry.io/otel/sdk/trace/tracetest` (`SpanRecorder`); acceptance tests
  query Tempo with the project's `internal/tempotest` helper.

## Commands

| Task                         | Command                                   |
|------------------------------|-------------------------------------------|
| Format                       | `make go-fmt PROJECT=<project>`           |
| Lint                         | `make go-lint PROJECT=<project>`          |
| Architecture rules           | `make go-arch PROJECT=<project>`          |
| Unit tests (race detector)   | `make go-test PROJECT=<project>`          |
| Integration tests (Tilt up)  | `make go-integration PROJECT=<project>`   |
| Acceptance tests (Tilt up)   | `make go-acceptance PROJECT=<project>`    |
| Mutation testing on the diff | `make go-mutate PROJECT=<project>`        |
| Vulnerability scan           | `make go-vuln PROJECT=<project>`          |
| Everything before review     | `make go-verify PROJECT=<project>`         |
